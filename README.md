# cloudsynth verify

Check a synthesized AWS CDK app against `cloudsynth.intent.yml` — the file that
states what your stack is *supposed* to do. Fails your build when it drifts.

```sh
npx cdk synth --all      # you already do this
npx cloudsynth init      # writes an intent file from what your stack already does
npx cloudsynth verify    # green, first try
```

Three commands from cold to gated. No YAML authored.

- **No network, ever.** No account, no API key, no telemetry, no update check.
  [Asserted against the published bundle](https://github.com/htah893A/cloudsynth/blob/main/SECURITY.md), not promised.
- **Zero runtime dependencies.** One 93 kB package, six files.
- **The CDK is not required.** It reads CloudFormation. SAM templates and
  hand-written CloudFormation work identically, both covered by tests.

## What `init` writes

It *evaluates* a catalog of 34 checks against your real templates. Rules that
already hold become active checks — which is why the first `verify` passes.
Rules that don't are written **commented out**, with what currently violates
them:

```yaml
# yaml-language-server: $schema=https://www.cloudsynth.dev/schema/intent-v1.json
# Generated by `cloudsynth init` — a snapshot of what this stack already does.
# Delete any check you don't mean; uncomment the ones you want to grow into.
version: 1
checks:
  - id: buckets-encrypted-at-rest
    description: Every bucket encrypts objects at rest
    select: AWS::S3::Bucket
    on-empty: pass
    assert:
      BucketEncryption: present

# 2 resources currently violate this — uncomment to enforce
#   - id: buckets-block-public-access
#     description: Every bucket blocks all four forms of public access
#     ...
```

Your backlog, in your own file, ready one line at a time. That first line makes
VS Code autocomplete the whole format.

## What a run looks like

```
  FAIL  Every bucket blocks all four forms of public access
        buckets-block-public-access  (from cloudsynth-pack-baseline@0.2.0)
        AppStack: Uploads: PublicAccessBlockConfiguration.BlockPublicAcls — expected true, found nothing
        Set blockPublicAccess: BlockPublicAccess.BLOCK_ALL.

  PASS  Every non-OPTIONS API method requires authorization  (58 resources, 4 exempted)
  PASS  No security group allows SSH from 0.0.0.0/0  (3 resources)

  2/3 checks passed against 2 template(s): AppStack, DbStack
  coverage: 156/751 resources examined across 57 type(s)
  nothing checks: AWS::Lambda::Permission (132), AWS::ApiGateway::Resource (81), and 46 more type(s)
```

**Exit codes:** `0` every error-severity check passed · `1` a check failed ·
`2` the input could not be read.

## In CI

**GitHub Actions.** Failures become annotations on the pull request —
`cloudsynth verify` detects the runner and switches format itself.

```yaml
- run: npx cdk synth --all
- run: npx cloudsynth verify
```

There is also an Action, if a `uses:` step is what you reach for. It does
exactly the same thing:

```yaml
- run: npx cdk synth --all
- uses: htah893A/cloudsynth-verify-action@v0
```

**GitLab CI**

```yaml
verify:
  image: node:22
  script:
    - npx cdk synth --all
    - npx cloudsynth verify --format text
```

**CircleCI**

```yaml
jobs:
  verify:
    docker: [{ image: cimg/node:22.11 }]
    steps:
      - checkout
      - run: npx cdk synth --all
      - run: npx cloudsynth verify --format text
```

**Anything else**

```sh
#!/bin/sh
set -e
npx cdk synth --all
npx cloudsynth verify --format text
```

## Exemptions

Real repositories have a resource that genuinely cannot be fixed this quarter.
Say so in the file, where review can see it. This is from CloudSynth's own
production intent file, the one gating every deploy of cloudsynth.dev:

```yaml
  - id: methods-have-auth
    description: Every non-OPTIONS API method requires authorization
    select: AWS::ApiGateway::Method
    where:
      HttpMethod:
        not: OPTIONS
    exempt:
      - match: RestApiServiceRestApistripewebhookPOST*
        reason: >-
          Stripe webhook. The caller is Stripe, which has no AWS credentials
          and no session; authenticity comes from the signature we verify on
          every request before reading the body.
    assert:
      AuthorizationType:
        not: NONE
```

```
PASS  Every non-OPTIONS API method requires authorization  (58 resources, 4 exempted)
```

An exemption excuses **one resource**, never the check — every other method is
still judged. `reason` is required. `until` **bites**: past that date the
exemption is ignored, the resource is judged again, and an unfixed violation
fails the run. An exemption matching nothing is reported as exempting nothing.

## Sharing rules between repositories

```yaml
version: 1
extends:
  - cloudsynth-pack-baseline
disable:
  - log-groups-set-explicit-retention
overrides:
  buckets-enforce-ssl:
    severity: warning
checks:
  - id: my-own-rule
    # ...
```

```sh
npm i -D cloudsynth cloudsynth-pack-baseline
```

A pack is a package containing a `cloudsynth.intent.yml` — no `bin`, no `main`,
no dependencies, nothing executable. Adopting a ruleset must not mean running
someone else's code in your CI.

Nearest wins: redefining a check id replaces the inherited one. `disable` drops
one outright. `overrides` adjusts `severity` **without** copying the check, so
it keeps receiving pack updates. Every check in the report records where it
came from — `local`, or `<pack>@<version>`.

## Coverage

Every run reports how much of the stack any check looks at, because "6/6 checks
passed" is true of a file that examines twelve resources out of seven hundred.

Name the types that must be fully examined and a gap becomes a failure:

```yaml
coverage:
  require:
    - AWS::Lambda::Function
```

```
  FAIL  coverage: AWS::Lambda::Function requires every resource be examined —
        ApiHandler, Worker, Scheduler are untouched.
```

Named individually, because a percentage tells nobody which resource to look
at.

## Editor support

```yaml
# yaml-language-server: $schema=https://www.cloudsynth.dev/schema/intent-v1.json
```

One line at the top of the file gives VS Code and anything else speaking the
YAML language server protocol completion, inline descriptions and validation as
you type. `init` writes it for you. The schema is generated from the same
definition the parser uses, and also ships in the package at
`cloudsynth/schema/intent-v1.json` for offline use.

**Expectations** are a literal value (deep-equal, or *included* when the
property is an array), `present`, `absent`, `{ not: <value> }`,
`{ at-least: n }`, `{ at-most: n }`, or a list of those, all of which must hold.

## Two semantics worth knowing

**An empty selection is not uniform, on purpose.** `every` and `any` *fail*
when nothing matches — silence about missing infrastructure would let an empty
stack read as passing intent. `none` *passes*, because "no security group
allows SSH from 0.0.0.0/0" is true of a stack with no security groups. Set
`on-empty: pass` to opt a positive check out of that.

**Across a multi-stack app**, `any` holds if it holds in any template; `every`
must hold in every template that *has* the resource (one with none of it
abstains); `none` must hold in every template. These rules have been wrong
twice in shipped releases, so a 45-cell matrix now enumerates them.

## The JSON report

`--format json` emits a versioned `ReportV1` that `text` and `github` are both
rendered from, so anything a human can see is something a machine can read.
Per check: `outcome`, `subjects`, `exempted[]`, `source`, `overridden`, and
structured `failures[]` with `stack`, `logicalId`, `path`, `expected`, `found`.
Plus `coverage.byType`, timings, and a `summary` carrying the exit code.

## Stability

**The intent-file schema (`version: 1`) and `ReportV1` are stable contracts —
additive-only while `version` is `1`. The package stays `0.x` until external
feedback settles, but the *file* contract is already what serious users are
trusting.**

New optional fields may appear; renaming or removing one requires a version
bump. Known gaps, deliberately not built: no regex or substring matching on
values, no cross-resource references, and CloudFormation `Conditions` are not
evaluated — a conditionally created resource is judged as though it exists.
